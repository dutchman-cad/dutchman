# CADIR v11 in Dutchman

Dutchman reads the wire and Rust types at cadmpeg commit
`ff2d6b32cfc95a40605c6d0e627ec0e45d6ff933`. The field map in cadmpeg's
`docs/cadir-v11.md`, section 9.2, describes the complete design vocabulary.
The pinned implementation also retains the `features` vocabulary in `model`;
its native readers still emit those records. `Design` is a separate namespace
whose records can restate the same identities. Dutchman continues to consume
the native readers' model history; it does not infer selections from design
names or substitute final topology for missing input geometry.

The wire accesses used by conversion, component extraction, appearances,
placement admission, and minimum reproductions follow these mappings:

| Previous access | V11 access |
| --- | --- |
| `ir.model.bodies`, `faces`, `edges`, and the other topology/carrier arenas | `ir.geometry`, a `Topology` |
| `Body.regions` | regions whose `body` names the body, in arena order |
| face entries in `Shell.members` | faces whose `shell` names the shell, in arena order |
| `Edge.start` and `Edge.end` | `Edge.ends`; missing ends have no vertex sample |
| a feature definition's `definition` discriminator | `definition.kind`, with its operation in `definition.value` |
| fields on a feature operation | the operation enum's `value` |
| fields on a solved curve or surface | `geometry.value` inside the `solved` arm |
| appearance target `id` | target `value` |
| prototype `scope`, external document `resolution` | `kind` |
| joint operands `arity` | `kind`, with operands in `value` |
| datum reference `reference`, sketch binding `space`, profile region `region`, face loops `classification`, NURBS poles `form` | `kind` |
| extrusion `ProfileRef` planar operand | `{"kind":"planar","value": <PlanarProfileRef>}` |
| loft guidance `path` | `value`; loft sections wrap a `profile` or `point` |
| revolve construction `state`, hole construction `construction` | `kind`, with construction fields in `value` |

The model's feature-input and result-topology arenas, `history_bodies`,
selections, profile references, and stored/body operations remain present in
this pin. Their existing mapping and refusal policies stay in place. Assembly
slices and standalone FreeCAD ownership walks index `geometry` and `model`
together without conflating `design`'s
restated identities. Imported region appearances follow the region directly,
without reconstructing the removed body membership field. The empty `native` home is written explicitly on slices;
v11 requires it even when there are no retained native records.

A document with only `design.features` is kept as final geometry with a specific
history refusal: its ordered selections and evaluation states have no
model-history projection. New `Selection`, sketch-region picks, `Stored`, and
body operations in that namespace are not inferred from final topology. Native
readers at this pin continue to use the retained model forms.

Synthetic JSON builders state empty lists, maps, and default values explicitly,
and omit absent optional values. They use the v11 wire directly. Expected
SolidCraft documents and placement fixtures are not regenerated by this port.
Empty-part builders clear both `geometry` and `model`; privacy assertions also
scan both homes for identities and names. Diagnostic carrier builders wrap
solved curves and surfaces in `{"kind":"solved","value": ...}`. Minimum
reproduction reports read solved surface categories from that payload while
retaining the outer `procedural` category for construction-backed surfaces.
Appearance test targets use `value`, and shell builders leave face ownership
on `Face.shell` rather than listing faces in `Shell.members`.
Synthetic view presentations state their required `properties` map explicitly.
Face appearance evaluation receives the complete solved surface enum; analytic
torus seam retries and spherical-corner picks read its `value` payload. Sketch
point-to-line dimensions resolve their line locus through `value` too.
Spreadsheet fixtures include their empty layout lists; tree nodes state empty
child membership, and NURBS surfaces state their normal orientation. Stored-body
fixtures copy topology from `geometry` and bind that home to the history context.
Whole-sketch profile fixtures use the operation and planar-profile wrappers;
rational spline checks change the poles' `kind` discriminator.

The Onshape REST bundle reader emits the same v11 wire. Its feature definitions
wrap an `operation` and that operation's `value`; extrusions additionally wrap
planar profiles. Revolve and hole construction payloads, sketch loci, NURBS poles,
and trimmed-region discriminators follow the pinned types. Equal-offset chamfers
state the former default `flip_direction: false` explicitly. Required empty feature
metadata, parameter dependencies and properties, sketch endpoint references, and
historical vertex membership are explicit. Final bodies and their solved carriers
come from the STEP decoder in `geometry`; the reader never rebuilds them from
rollback selections. Parameter ordinals remain local to each owning feature.

Onshape thin walls pair a typed `design.features` extrusion with the existing
`model.features` projection by feature identity. The typed `output.body` carries
the thin thickness and side; profile, direction, extent and Boolean semantics
must agree with the projection before the writer uses it. This narrow bridge does
not admit design-only histories or infer absent projection operands.
