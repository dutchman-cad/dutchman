Dutchman Convert 0.3.0 opens Fusion, Inventor, SolidWorks and FreeCAD files straight from SolidCraft with the new Dutchman plugin, and reads Onshape for the first time. SolidCraft 0.45 is the newest target, with designs that open in SolidCraft 0.18.2 to 0.45. Much more Fusion history stays editable, and the desktop app makes it easy to tell us when something is wrong.

## What's new

- **Dutchman inside SolidCraft.** Install the Dutchman plugin with Preferences > Plugins > Install plugin… in SolidCraft 0.44 or newer (desktop) and approve its memory request (a plugin copied into the plugins folder by hand isn't approved and is refused for memory), then open Fusion, Inventor, SolidWorks and FreeCAD files directly, with editable history. SolidCraft's Import report lists what could not be carried over in plain lines, and the plugin checks the history in SolidCraft itself, so a history that matches the original opens as the visible model. Each release attaches `dutchman-plugin-X.Y.Z.zip`.
- **Onshape support.** Connect your Onshape account from the app or with `dutchman onshape login`, using your own API keys or an OAuth bearer token, then paste a Part Studio link or use `dutchman onshape fetch`. Dutchman saves an offline bundle beside the converted design and keeps sketches, extrudes, revolves, fillets and chamfers (including tangent-propagated ones), tapped and blind holes, thin walls, symmetric extrudes and variables editable. Derived Part Studios stay linked to local SolidCraft designs. Anything not supported yet keeps the final shape and says why.
- **SolidCraft 0.44 support.** SolidCraft 0.44 is the newest target. On 0.44 and newer, extrudes from or to a flat face at a slant to the sketch, 3D sketch dimensions and relations, and more multi-body joins, cuts and intersections stay editable. On 0.44.1 and newer, fillets and chamfers on a full circle, such as the rim of a hole, stay editable too.
- **More Fusion history stays editable.** Chamfers with two different distances, contour flanges, Split Body, Copy/Paste Bodies, mirrored-then-removed bodies, symmetric patterns, Base Features that later steps change, clockwise sketch arcs, narrow profile regions such as belt teeth, surface revolves of open curves, and sweep paths made of connected edges all keep their history. An extrude whose profile Fusion does not record is kept when exactly one sketch region, rebuilt in SolidCraft, matches the original, and the report marks it `inferred`. Tapped blind holes keep their thread length and hand (SolidCraft 0.40 and newer) and an ISO tolerance class (0.43 and newer), holes on box primitives and on faces with rounded corners convert, countersink holes that end at a face with a drill point convert, through-all counterbores and countersinks with a drill point convert, and extrudes and revolves that use the whole result of an earlier sketch feature keep their history. Cosmetic threads keep their nominal size when Fusion's table values are rounded.
- **Tell us when something is wrong.** "Is there a problem? Is something missing?" is always in the desktop window: join our Discord, DM Dutchy the file, or open a GitHub issue. Report this file… on each result opens it for that file. Partial and geometry-only results show in the warning color, Stop ends a conversion promptly, and the window's fields and buttons line up.
- **Batch reports, paste, share links and a look first.** After a folder run, Batch report writes `dutchman-batch-report.md` and `.csv` into the output folder: a totals line, then one row per file with its outcome (full history, partial N of M, geometry only, or failed) and the first reason. From the command line: `convert-all --batch-report`, or `batch-report <folder>`. Paste files, paths, Onshape links or HTTPS CAD file links into the app, or paste a public Fusion or Google Drive link to download and convert it. `dutchman convert <url>` works too. Links to private, local or cloud-metadata addresses are refused. `dutchman contents` and the MCP `contents` tool list a file's bodies, timeline and parameters, and which features map to SolidCraft, without converting; conversions show which feature they are on.
- **More formats, options and fixes.** Siemens NX parts convert their geometry. `--stand-up` turns Y-up models, such as older Fusion designs, into SolidCraft's Z-up. A SolidWorks assembly whose parts cannot be found says so. Reports carry the exact verification tolerances used, link each history row to the features it produced, and can be counts only. On Windows the command line no longer crashes with a stack overflow (exit 0xC0000409), choosing a `solidcraft-cli` older than 0.18.2 says so, designs with surface bodies are checked against the original again on SolidCraft 0.23 and newer, and variable fillets and chamfers on closed edges that aren't circles now say exactly why they can't stay editable yet.

## Known issues

- SolidCraft's default plugin fuel limit (Preferences > Plugins > Max plugin fuel, 100,000,000,000) is too low for large assemblies: the plugin then stops with a fuel error. Raise it (700,000,000,000 opens a 41-part arm).
- Some Fusion assemblies, for example ones whose parts are linked inside the archive, now report "N parts couldn't be placed" instead of quietly placing them at the origin; reading those positions is next ([dutchman-cad/dutchman#858](https://github.com/dutchman-cad/dutchman/issues/858), [cadmpeg/cadmpeg#1880](https://github.com/cadmpeg/cadmpeg/issues/1880)).
- The SolidCraft plugin takes a while to start the first time you open a file in a session; later opens are faster. Very large designs are refused by the plugin with a pointer to the Dutchman app ([dutchman-cad/dutchman#781](https://github.com/dutchman-cad/dutchman/issues/781)).
- A Fusion assembly saved as `.f3d` whose parts are linked from other designs comes in without those parts; Dutchman now says so and marks it unverified. Export it as `.f3z`, or keep the linked designs' `.f3d` files next to it; picking those up automatically is next ([dutchman-cad/dutchman#785](https://github.com/dutchman-cad/dutchman/issues/785)).
- Fusion's own STEP export leaves out hidden bodies, so a Dutchman conversion (which keeps them, marked hidden) can show more bodies than your STEP export.
- A kept feature can replay from the wrong sketch region and still be counted as kept; the final shape is unaffected, because it comes from the source design ([dutchman-cad/dutchman#489](https://github.com/dutchman-cad/dutchman/issues/489)).
- Some large Fusion `.f3d` designs reach the 900 s limit for one file while being read ([dutchman-cad/dutchman#604](https://github.com/dutchman-cad/dutchman/issues/604)).

Versions: cadmpeg at commit f1338aa2, SolidCraft 0.18.2 to 0.45 (0.45 newest).
